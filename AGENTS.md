# Project work rules

- Communicate with the user in Simplified Chinese.
- Write code, identifiers, comments and docstrings in English.
- Inspect the current branch, remote, applicable instructions and existing edits before making changes.
- Keep public branding in config/site.json and internal names independent of it.
- Preserve existing external resources, persisted formats and user data unless a migration is explicitly planned and verified.
- Use only authorized tools and repositories. Never write credentials to code, logs or archives.
- Preserve user work; do not force-push, reset destructively or delete resources.
- Run checks appropriate to the change; record actual results and any limitations.
- Maintain PROJECT_STATUS.md, TODO.md and DEVLOG.md without discarding history.
- Obtain push authorization, save changes on a review branch, and verify the remote SHA before claiming remote persistence.
